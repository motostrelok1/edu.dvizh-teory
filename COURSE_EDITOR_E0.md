# COURSE_EDITOR_E0 — Архитектура и решения перед реализацией

Статус: **предложение на согласование (E0), без изменения работающего приложения**  
Дата: 2026-10-13  
Основание: [COURSE_EDITOR_SPEC.md](COURSE_EDITOR_SPEC.md)

## 1. Рекомендуемая архитектура

- Интерфейс: существующее React + TypeScript + Vite приложение; закрытый маршрут администратора `/admin/course`.
- Хранилище: **Supabase PostgreSQL**, файлы — **Supabase Storage**. По умолчанию **отдельный Supabase-проект для учебника** до решения о едином входе с автошколой. Не подключать напрямую администраторские service-role ключи в браузере.
- Публичное чтение: опубликованные **версионированные JSON-снимки** или read-only API. Действующий `public/sections.json` оставить резервной стабильной версией до проверенной миграции.
- Операции редактора: только с подтверждённой ролью; права контролируются RLS и/или серверными функциями. Публикация выполняется атомарно, без частичных состояний.

### Ключевые сущности

| Сущность | Назначение |
|---|---|
| `courses` | Идентификатор, название, статус курса |
| `sections` | Постоянный UUID, legacy ID (например, `s1`), порядок, заголовок, архив |
| `section_drafts` | Редактируемая схема блоков, номер версии для обнаружения конфликтов |
| `section_revisions` | Неизменяемые снимки публикаций, автор, дата, комментарий |
| `section_publications` | Ссылка на текущую опубликованную ревизию |
| `media_assets` | Путь файла, тип, размеры, хэш, атрибуты доступности |
| `course_audit_log` | История изменений, откатов и публикаций |
| `course_members` | Роли `admin` / `editor` (после согласования) |

*Поля, ограничения, индексы и RLS оформляются миграциями на E1 после выбора проекта.*

## 2. Версионированная структура блоков

Существующие типы `p`, `h2`, `img`, `motivation`, `topic`, `lead`, `quote`, `term`, `example`, `quiz` сохраняются на миграции. Добавить:
- `schemaVersion` всему содержимому;
- постоянный `id` каждому блоку и вопросу;
- управляемый `link` как типизированный inline-фрагмент: `sectionId`, `blockId` (опционально), `signCode` / `markupCode` или `https URL`;
- у изображения: `assetId`, `widthPercent` (20–100), `maxWidthPx`, `align`, `alt`, `caption`.

Для текста с несколькими ссылками использовать массив типизированных фрагментов (text + link), а не произвольный HTML. Ограничение 330 px в текущих компонентах снять только при внедрении нового рендера и проверке на мобильном экране.

## 3. Защита нормативных данных

- **Нормативный текст** (`quote`): защищён от обычного редактирования, хранит источник и редакцию; изменения проводятся через отдельную проверку администратором.
- **Авторский материал** (`lead`, `motivation`, `example`, `topic`, `term`): редактируется свободно с историей версий.
- Python-генераторы **не пишут напрямую** в рабочие черновики или публикации. Они готовят отдельный импорт-предложение с diff.
- Старые опубликованные версии и результаты тестов остаются воспроизводимыми.

## 4. Миграция без потери существующего курса

1. Зафиксировать SHA текущего `sections.json` и список файлов `public/img`, сохранить резервную копию.
2. Присвоить UUID в базе каждому из 30 разделов, сохранить исходные строковые ID для старых URL и отметок прогресса.
3. Воспроизводимо назначить ID блокам, проверить число и порядок блоков, иллюстраций и вопросов.
4. Импортировать файлы в медиабиблиотеку и проверить, что каждая ссылка на изображение разрешается.
5. Сравнить отображение и переходы с существующим приложением. Проверить мобильные размеры и быстрые переходы на знаки/разметку.
6. Переключить чтение на опубликованный снимок только после полного теста; предусмотреть немедленный откат на старую статическую версию.

## 5. Интерфейс редактора — структура экранов

- **Список разделов**: поиск, порядок, создать/дублировать/архивировать, черновик/опубликован.
- **Редактирование страницы**: дерево блоков, центральная область с прямым редактированием, панель свойств выбранного блока.
- **Медиабиблиотека**: загрузить/выбрать/заменить, проверить использование, alt-текст.
- **Предпросмотр**: desktop/mobile, без публичного отображения черновика.
- **Публикация и версии**: сравнение с действующей версией, проверки ссылок, история ревизий, откат.

## 6. Безопасность и тестируемость

- Нет открытых ключей с привилегией администратора; RLS на редактирование, медиа и публикацию.
- Валидация всех блоков на серверной стороне, защита от HTML/JS и опасных URL, ограничение размеров и форматов изображений.
- Отдельные тесты импорта, ссылок, публикации, отката, конфликтов и прав.
- CI обязателен для PR, деплой отделён от проверки.

## 8. Решения, которые нужно утвердить

1. **База:** отдельный Supabase-проект учебника (рекомендуется) или единый с основной автошколой.
2. **Публикация:** только администратор (рекомендуется для MVP) или отдельные редакторы с правом публикации.
3. **Материалы:** официальные пункты ПДД защищены, авторские объяснения доступны для редактирования (рекомендуется).
4. **Медиаблок:** ширина, выравнивание, подпись и alt в MVP; обрезка — позже (рекомендуется).
