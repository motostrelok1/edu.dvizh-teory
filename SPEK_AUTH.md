# СПЕКА: Регистрация и авторизация пользователей (edu.dvizh-school.ru)

Статус: **проект спецификации, реализация не начата**
Дата: 2026-10-03

---

## 1. Цель

Добавить на сайт учётные записи курсантов: регистрацию с обязательными полями,
вход по логину/паролю, подтверждение e-mail и особый сценарий для
несовершеннолетних (согласие родителя). В перспективе — привязка прогресса
обучения к аккаунту и уведомления.

## 2. Текущее состояние платформы (важно для архитектуры)

- Сайт полностью **статический** (React SPA + `sections.json`), отдаётся nginx с VDS.
- Прогресс обучения хранится в `localStorage` браузера, без привязки к пользователю.
- Бэкенда, базы данных и механизма отправки писем **нет**.

**Вывод:** регистрация требует серверной части. Вариант: Node.js (Express/Fastify)
на том же VDS за nginx, БД PostgreSQL или MySQL, SMTP-отправка писем.
Решение принять на этапе реализации (раздел 9).

## 3. Регистрация

### 3.1. Поля формы (все обязательные)

| Поле | Формат | Валидация |
|---|---|---|
| Фамилия | строка | не пусто, буквы/дефис |
| Имя | строка | не пусто |
| Отчество | строка | не пусто |
| Дата рождения | ДД.ММ.ГГГГ | валидная дата; возраст от 14 лет (ниже — отказ с пояснением, см. 3.4) |
| Телефон | `+7 (xxx) xxx-xx-xx` | маска ввода; префикс `+7` зафиксирован, вводится только остаток 10 цифр; проверка на полноту |
| E-mail (логин) | почта | формат e-mail; проверка уникальности (занят — ошибка «такой адрес уже зарегистрирован») |
| Пароль | строка | минимум 8 символов, латиница+цифры; индикатор надёжности |
| Повтор пароля | строка | совпадение с паролем |

### 3.2. Согласия (чекбоксы)

1. **«Согласен с обработкой персональных данных»** — обязательный.
   Пока галочка не стоит, кнопка «Зарегистрироваться» **неактивна**.
   Рядом ссылка на документ «Политика обработки персональных данных»
   (документ нужно подготовить, см. раздел 8).
2. **«Получать Push-уведомления и уведомления на почту»** — по ТЗ тоже
   обязательный для активности кнопки: пока не стоит галочка, кнопка неактивна.
   ⚠️ *Открытый вопрос:* обычно такая галочка добровольная. Подтвердить,
   что она именно блокирует регистрацию (раздел 10).

Кнопка «Зарегистрироваться»: активна только когда все поля валидны
и обе галочки отмечены.

### 3.3. Сценарий «после отправки формы»

1. Сервер создаёт аккаунт со статусом `email_not_confirmed`,
   пароль хранится только в виде хэша (argon2/bcrypt).
2. На указанный e-mail отправляется письмо со **ссылкой подтверждения**
   (одноразовый токен, срок жизни 24 часа).
3. Пользователь показывается экран «Мы отправили письмо на вашу почту».
4. **Первый вход возможен только после подтверждения e-mail:**
   неподтверждённый аккаунт при попытке входа получает сообщение
   «подтвердите почту» с кнопкой «отправить письмо повторно».
5. Дата рождения проверяется сервером (не доверяем данным формы):
   - **18 и старше** → вход в личный кабинет, обычный режим.
   - **менее 18** → модалка согласия родителя (раздел 4) до первого доступа к курсу.

### 3.4. Минимальный возраст

Регистрация самостоятельная — с 14 лет (согласно СК РФ с 14 возможно
самостоятельное согласие на обработку ПДн в отдельных случаях; для автошколы
обучение обычно с 16–17). *Открытый вопрос:* какой нижний порог ставим
(14 / 16 / как в автошколе)? До решения — 14+ со сценарием раздела 4.

## 4. Модалка «Вы несовершеннолетний» (показывается при первом входе, если < 18)

Текст-заголовок: небольшое пояснение («Вам нет 18 лет, поэтому требуется
согласие законного представителя»).

Поля (все обязательные):

| Поле | Формат |
|---|---|
| Фамилия Имя Отчество родителя | строка (три поля или одно — на этапе дизайна) |
| E-mail родителя | формат почты |
| Телефон родителя | маска `+7 (xxx) xxx-xx-xx` |

В тексте модалки обязательно указать:

- на указанную почту родителя **придёт уведомление** о регистрации ребёнка;
- родитель может **наблюдать статус прохождения курса**
  (прогресс по разделам, результаты тестов) — в текущей версии это
  оповещение-заглушка, личный кабинет родителя — отдельная задача.

Кнопка «Подтвердить и продолжить» — активна при заполненных валидных полях.
Данные родителя сохраняются в профиле ученика как `parent: {...}`.

## 5. Авторизация (вход)

- Поля: **логин (e-mail)** + **пароль**, кнопка «Войти».
- Ссылка «Забыли пароль?» → восстановление по e-mail (одноразовая ссылка,
  сброс пароля).
- Ссылка «Регистрация» → форма из раздела 3.
- Опция «Запомнить меня» (сессия 30 дней vs сессия до закрытия браузера).
- После входа пользователь возвращается в учебник; прогресс теперь
  привязывается к аккаунту (синхронизация из localStorage — раздел 7).

## 6. Хранение прогресса после внедрения аккаунтов

- Прогресс («Изучено» по разделам, результаты тестов) сохраняется на сервере
  в привязке к `user_id`.
- При первом входе после регистрации: предложить перенести текущий
  localStorage-прогресс в аккаунт (однократный диалог «Найден прогресс
  на этом устройстве — перенести?»).
- Для гостей (не вошедших) сайт продолжает работать как сейчас,
  с localStorage; кнопка «Войти/Регистрация» в шапке.

## 7. Уведомления (описано для спеки, реализация отдельными задачами)

- **E-mail:** сервисные письма (подтверждение, восстановление пароля,
  уведомление родителю), учебные дайджесты (если галочка раздела 3.2 п.2).
- **Push:** Web Push (VAPID) — для статического сайта стандартный путь
  без мобильного приложения. Подписка запрашивается после входа,
  не на этапе регистрации.

## 8. Персональные данные (152-ФЗ) — обязательно до запуска

- Подготовить документ «Политика обработки персональных данных»
  и публиковать его на сайте со ссылкой из формы регистрации.
- Храним: ФИО, дату рождения, телефон, e-mail, ПДн родителя несовершеннолетних.
- Требования: шифрование по каналу (HTTPS — есть), хэш паролей,
  ограничение доступа к БД, сроки хранения, возможность удаления аккаунта
  по запросу (кнопка «Удалить аккаунт» в профиле).
- Обработка ПДн несовершеннолетних — только с согласия родителя (модалка
  раздела 4 является фиксацией этого согласия; желательно письмо-уведомление
  родителю со ссылкой «отозвать согласие»).

## 9. Архитектура (черновик для обсуждения)

- **Backend:** Node.js + Fastify/Express на том же VDS (порт, например, 3001),
  nginx проксирует `/api/*` на него. Альтернатива — отдельный поддомен api.*.
- **БД:** PostgreSQL (или MySQL) на VDS; таблицы `users`, `parents`,
  `email_tokens`, `progress` (`user_id`, `section_id`, `done`, `quiz_results`).
- **Авторизация:** сессионные cookie (httpOnly, secure) или JWT —
  выбрать на реализации; предпочтительно cookie + CSRF-токен.
- **Почта:** SMTP (можно через тот же домен: почта для dvizh-school.ru)
  или сервис-шлюз (Unisender Go, Яндекс 360 для домена).
- **Регистрация push:** Service Worker + Web Push (VAPID-ключи сервером).
